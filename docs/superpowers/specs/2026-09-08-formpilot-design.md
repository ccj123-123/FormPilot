# FormPilot：AI 参数化桌面收纳设计师

## 1. 文档状态

- 日期：2026-09-08
- 状态：设计已确认，尚未开始实现
- 实施周期：7 天
- 总预算上限：500 元人民币
- 使用者背景：Python、JavaScript 和 3D 建模均为初学者
- 实物制造方式：淘宝 3D 打印代加工

## 2. 项目定位

FormPilot 面向没有 3D 建模经验、希望定制桌面收纳底座的普通用户。用户用自然语言描述需求并填写设备尺寸，系统将需求转换为受约束的参数化设计，生成可预览、可校验、可下载并可交付打印的 STL 文件。

项目重点不是任意文本生成 3D，而是展示一条稳定、可解释的创作闭环：

```text
自然语言需求 → 信息追问 → 结构化参数 → 制造规则校验
→ 参数化建模 → STL 网格校验 → 淘宝打印 → 实物反馈 → 第二版参数
```

## 3. 目标与非目标

### 3.1 目标

1. 支持手机、耳机盒和理线孔三个功能模块。
2. 支持并排式、前后式两种固定布局。
3. 使用 AI 提取参数、发现缺失信息、解释设计和提出修改建议。
4. 使用确定性程序完成尺寸校验、几何生成和 STL 有效性判断。
5. 在单页界面中完成输入、预览、检查和下载。
6. 至少完成一次淘宝实物打印，并保留 V1 到 V2 的反馈证据。

### 3.2 非目标

- 不根据照片自动测量真实尺寸。
- 不支持任意形状或自由曲面建模。
- 不做图片生成 3D。
- 不自动调用淘宝下单。
- 不实现账号、权限、数据库和云端多用户服务。
- 不搭建多 Agent 框架。
- 不实现专业级切片或打印机控制。

## 4. 用户流程

1. 用户输入自然语言，例如：“给我的手机和耳机做一个不超过 180 mm 宽的极简收纳座，需要理线孔。”
2. AI 将描述解析为固定结构，并判断必要尺寸是否齐全。
3. 若缺少手机厚度等必要字段，系统只追问缺失字段，不猜测数值。
4. 用户补充尺寸，并选择并排式或前后式布局。
5. 程序执行数值范围和制造规则校验。
6. 校验通过后，系统将参数传入 OpenSCAD 模板并导出 STL。
7. Trimesh 检查网格、包围盒和封闭性。
8. 页面展示可旋转的 3D 预览、设计说明和检查报告。
9. 用户下载 STL 与参数 JSON，交付淘宝商家打印。
10. 用户记录槽位松紧和底座稳定性；系统按固定规则生成 V2 参数及 STL。

## 5. 界面设计

应用只有一个 Gradio 页面。

### 5.1 左侧：需求与参数

- 自然语言需求输入框
- “AI 解析需求”按钮
- 手机宽度与厚度输入框
- 耳机盒宽度与厚度输入框
- 最大底座宽度输入框
- 布局选择：并排式、前后式
- 配合间隙、底板厚度和理线孔开关
- “生成模型”按钮
- 打印反馈区域：太紧、合适、太松、底座是否稳定及备注

### 5.2 右侧：结果

- STL 三维预览
- AI 设计说明
- 制造与网格检查报告
- STL 下载按钮
- 当前参数 JSON 下载按钮
- V1 与 V2 参数差异

Gradio `Model3D` 支持显示 STL 文件，可避免额外开发 Three.js 前端。

## 6. 技术架构

采用 Python 单体应用，不做前后端分离。

```text
Gradio 页面
    ↓
需求解析器
    ↓
DesignSpec
    ↓
确定性规则校验器
    ↓
OpenSCAD 参数化模板
    ↓
STL
    ↓
Trimesh 网格检查
    ↓
预览、报告与下载
```

### 6.1 模块边界

- `app.py`：页面布局、按钮事件、状态和结果展示。
- `src/design_spec.py`：参数对象、单位、默认值和类型约束。
- `src/requirement_parser.py`：大模型调用、结构化输出、缺失字段识别。
- `src/validator.py`：范围、布局和制造规则；不依赖大模型。
- `src/model_generator.py`：渲染 OpenSCAD 参数并执行 STL 导出。
- `src/mesh_checker.py`：网格、包围盒、连通体和封闭性检查。
- `src/revision.py`：把实物反馈转换为确定性的参数变化。
- `templates/desk_organizer.scad`：唯一的参数化几何模板。

各模块通过 `DesignSpec` 和检查报告对象通信，不读取其他模块内部状态。

## 7. 数据设计

所有长度单位统一为毫米。核心参数示例：

```json
{
  "layout": "side_by_side",
  "phone_width": 76.0,
  "phone_thickness": 10.0,
  "earbuds_width": 65.0,
  "earbuds_thickness": 28.0,
  "max_base_width": 180.0,
  "clearance": 1.2,
  "base_thickness": 5.0,
  "slot_depth": 15.0,
  "phone_tilt_degrees": 15.0,
  "cable_hole_enabled": true,
  "cable_hole_diameter": 8.0
}
```

参数 JSON 与 STL 同时保存，保证任何模型都能追溯到生成它的输入。

## 8. Agent 决策设计

大模型每次只能返回以下动作之一：

- `ask_user`：必要字段缺失，返回缺失字段列表与一个简短问题。
- `generate`：信息完整，可以进入确定性校验。
- `revise`：用户输入明显矛盾，给出修改建议但不生成模型。
- `explain`：解释当前设计，不修改参数。

固定状态流：

```text
RECEIVED
  → PARSED
  → NEEDS_INPUT 或 READY
  → VALIDATED 或 REJECTED
  → GENERATED 或 GENERATION_FAILED
  → CHECKED 或 MESH_FAILED
  → DELIVERED
```

大模型负责理解、追问和解释；程序负责尺寸、制造安全、几何与最终有效性判断。

## 9. 参数与制造规则

### 9.1 默认值

- 配合间隙：1.2 mm
- 底板厚度：5 mm
- 插槽深度：15 mm
- 手机倾角：15°
- 理线孔直径：8 mm
- 最小壁厚：3 mm
- 模块间最小距离：3 mm

所有默认值必须显示在页面上并允许修改。

### 9.2 输入范围

- 手机宽度：55–100 mm
- 手机厚度：5–20 mm
- 耳机盒宽度：40–90 mm
- 耳机盒厚度：15–50 mm
- 最大底座宽度：120–260 mm
- 配合间隙：0.5–2.5 mm
- 底板厚度：4–10 mm
- 理线孔直径：5–15 mm

### 9.3 校验规则

1. 所有尺寸必须为有限正数并处于允许范围。
2. 手机槽开口等于手机厚度加两侧配合间隙。
3. 耳机槽开口等于耳机盒厚度加两侧配合间隙。
4. 壁厚不得小于 3 mm，底板不得小于 4 mm。
5. 两个功能模块之间至少保留 3 mm。
6. 计算后的底座宽度不得超过用户设定值。
7. 导出的 STL 必须含有顶点和三角面。
8. STL 包围盒必须与计算尺寸在允许误差内一致。
9. 最终模型必须为单个预期连通体和封闭网格。

## 10. 异常处理与降级

- 大模型返回非法 JSON：以相同输入自动重试一次；再次失败后切换到手动表单。
- 缺少必要字段：停止建模，只返回缺失字段及追问。
- 数值越界：指出字段、当前值和允许范围。
- 布局超出最大宽度：建议增大限制或切换为前后式。
- OpenSCAD 返回非零退出码：保存可读错误摘要，不展示或下载损坏文件。
- STL 为空或不封闭：重新导出一次；仍失败则终止并保留上一次成功结果。
- 大模型 API 不可用：手动参数模式仍可完整生成 STL。
- 生成超时：终止本次执行，页面继续展示上一次成功结果。
- 每次输出使用唯一运行目录，防止连续生成时文件互相覆盖。

API 密钥只从环境变量读取，不写入源码、日志或参数文件。用户需求发送给模型前不包含本地路径和无关个人信息。

## 11. 实物反馈闭环

V1 打印后记录：

- 手机槽：太紧、合适或太松
- 耳机槽：太紧、合适或太松
- 底座：稳定或不稳定
- 实测成品尺寸和自由备注

固定调整规则：

- 太紧：对应间隙增加 0.3 mm。
- 太松：对应间隙减少 0.2 mm，但不得低于 0.5 mm。
- 不稳定：底板厚度增加 1 mm；若已达上限，则增加底座前后深度。

系统保存 `v1.json`、`feedback.json`、`v2.json` 和 `v2.stl`，并生成差异摘要。V2 是否再次打印由 V1 的问题严重程度和剩余预算决定。

## 12. 测试设计

至少覆盖以下场景：

1. 正常尺寸生成并排式模型。
2. 正常尺寸生成前后式模型。
3. 缺少手机厚度时进入 `ask_user`。
4. 负数、文本和超范围数值被拒绝。
5. 底座宽度不足时给出可执行建议。
6. 大模型返回非法 JSON 时重试并降级。
7. API 断网时手动参数模式可用。
8. OpenSCAD 失败时不提供损坏文件。
9. 网格不封闭时终止下载。
10. 连续生成不同参数时输出文件互不覆盖。
11. V1 反馈能够生成符合规则的 V2 参数。

最终验收时，使用至少 5 组不同设备尺寸生成并打开 STL，并在切片软件中检查其中一组。

## 13. 七天实施安排

### 第 1 天：最小建模链路

- 建立项目结构和 `DesignSpec`。
- 创建最简单的 OpenSCAD 模板。
- 用固定参数从命令行导出 STL。
- 在切片软件中确认文件能打开。

### 第 2 天：完整参数化模板

- 完成手机槽、耳机槽、理线孔及两种布局。
- 加入间隙、壁厚、底板和倾角参数。
- 生成真实设备的 V1，并在当天交付淘宝商家打印。

### 第 3 天：Gradio 页面

- 完成表单、生成按钮、3D 预览和文件下载。
- 展示当前参数与检查结果。

### 第 4 天：AI 需求解析

- 接入结构化输出。
- 完成参数提取、缺失字段追问和一次重试。
- 完成 API 失败时的手动模式。

### 第 5 天：规则与测试

- 完成参数校验和 Trimesh 检查。
- 覆盖主要正常、异常和降级测试。
- 准备一套离线演示数据。

### 第 6 天：实物反馈

- 若实物已收到，测量并记录 V1 问题，生成 V2。
- 若未收到，使用商家切片截图证明文件可生产；收到后再补实物证据。

### 第 7 天：作品集包装

- 完成 README、架构图、V1/V2 对比和项目复盘。
- 录制 60–90 秒 Demo。
- 在干净环境中完成一次最终演示。

## 16. 验收标准

项目只有同时满足以下条件才算完成：

- 本地单页应用可以稳定启动。
- 自然语言可以转换为结构化参数。
- 缺少信息时系统会追问而不是猜测。
- 两种布局都能生成可预览的 STL。
- 非法参数和无效网格会被阻止。
- API 断网时仍能使用手动参数模式。
- 至少 5 组尺寸通过自动测试。
- 至少一个 STL 能被切片软件正常打开。
- V1 已交付淘宝打印并留有订单或商家校验凭证。
- 保存 V1、反馈和 V2 的可追溯数据。
- 完成 README、架构说明和 60–90 秒演示视频。

若第 7 天实物仍在运输中，软件 MVP 可以结束，但项目对外只能描述为“已完成可制造性校验并送印”；收到并验证实物后才能描述为“完成实物闭环”。

## 17. 主要风险与控制

- **学习曲线过陡**：只使用 Python、Gradio 和一个 OpenSCAD 模板，不做前端分离。
- **AI 输出不稳定**：使用固定结构、有限动作、一次重试和手动降级。
- **几何难以维护**：AI 不编写几何；所有形状由参数化模板生成。
- **物流延误**：第 2 天下单，保留商家切片截图作为阶段证据，实物到达后补验证。
- **预算超支**：V2 默认只生成文件，有明确验证价值时才二次打印。
- **现场网络故障**：准备手动模式、离线示例和上一次成功模型。
